MoRead 设计规范

一个只读 Markdown 阅读器的完整视觉系统。所有值都已落成 CSS 变量，tokens.css 直接引入即可用；本页本身就是这些令牌的活体演示——右上角切主题，看到的每个颜色都是真实令牌。

核心立场：阅读器的装饰每多一分，读者的注意力就少一分。所以这套系统里没有阴影、没有渐变、没有大圆角、没有高饱和色，全靠 1px 细线、六级灰阶和一个墨绿强调色撑起层级。

1色彩

每个色板左半为浅色值、右半为深色值，下方两行分别标注。深色不是「浅色反相」，而是重新调过的一套暖墨色——底色偏暖、强调色提亮，保证正文对比度仍达 9:1 以上。

1.3 强调色

没有用常规的蓝色链接色。选了松墨绿——贴合「墨读」的纸质调性，且在暖纸底上对比度 6.1:1 达标 AA，在深色底上 7.5:1。每个界面只允许出现一个强调色，不叠加第二个。

只有"变"的东西进覆盖块：表面 / 描边 / 文字 / 强调软色；字体、字号、圆角、间距、阴影一律不动。每加一族要写两个块（浅 + 深）—— 漏了深色块会出现"深色模式下还是浅色纸底"这种最刺眼的 bug。深色块用 [data-palette="x"][data-theme="dark"]，两个属性选择器稳压基础深色块，所以不必把深色值再抄一遍。

外观面板里的色卡不是画出来的色块，而是给元素挂上 data-palette / data-theme 让令牌自己算 —— 因此永远不会有"色卡过期"的问题。

2.1 字体族

排版铁律

阅读列宽 ≤ 680px超过 680px 眼睛要来回扫行。窗口再宽，正文列宽也不放宽——默认 680，用户可在 600–1400 间调
中文行高 ≥ 1.7汉字是方块字，1.5 行高会挤。正文用 26px/15px ≈ 1.73
标题 serif，正文 sans文档级标题一律 Source Han Serif；UI 与正文一律 Noto Sans SC。不混用
正文左对齐除空态与引导页的居中说明外，正文永不居中、永不两端对齐

2.4 正文字号可调（12–22 px）

只有一个旋钮：正文字号，默认 15px。其余 13 级不单独调，按同一倍率联动。

范围 / 步进12–22px，1px 一档；默认 15。再小读不动，再大会把 680px 版心压成窄条
载体--mr-read-scale（1 = 15px）写在 <html> 上
生效范围仅 .mr-article 子树——它在自己身上重算 11 组字号 / 行高令牌
界面读 :root 原值，任何档位都不跟着放大：标签页、侧栏、面板像素级不变
版心--mr-reading-w 固定不缩放——放大的是字，不是纸
入口外观面板 − 15px +、Ctrl+滚轮、Ctrl+= / Ctrl+- / Ctrl+0
两个理由：① 铁律 2 在任意档位都成立——行高与字号同倍率，比值恒为 1.73。② 不做整页 zoom：那会连工具栏一起放大，读起来像浏览器按错了键。阅读器要调的是「字」，不是「界面」。

3.3 阴影

5.7 三态规范

加载中
骨架屏用 --mr-surface-track，不用转圈
空
说清「为什么空」并给一个动作。
例：还没有打开过文件 → 给「打开文件」按钮
错误
写清发生了什么 + 下一步怎么办。
文件缺失 → 显示原路径 + 「移除标签」
硬要求：任何数据面都必须实现这四态——加载 / 空 / 错误 / 成功。禁止静默失败，禁止留白让人猜。

5.8 历史行与右侧搜索栏

对象规则
历史行结构文档图标 · 文件名 12px/500 · 所在目录 10px mono（只取最后一级）· 相对时间 10px mono
当前项文件名转 --mr-accent，与激活标签同一语义
缺失项整行降到 --mr-text-6、disabled、行尾挂「已不存在」细边标签，不给任何 hover 反馈
历史上限24 条——再多就从「能找回的东西」变成需要检索的档案馆
搜索栏宽度min(336px, 34vw)，下限 260；占位时正文收到 min(680, 可用宽度)，绝不横向裁切
范围切换三档分段：当前标签 / 所有标签 / 工作区；没有工作区时第三档置灰
结果顺序按文件分组，组顺序只按文件名，永不因「谁是当前文档」重排；当前文档只把文件名转 --mr-accent 标出，位置不动
两条判断：① 缺失状态是每次启动探测出的当下事实，不写进存储——文件放回去了，列表不能还灰着。② 搜索放右侧而不是左侧：左侧回答「我的文档在哪」（常驻导航），右侧回答「这段内容在哪」（临时任务，用完即收）。
一条硬规则：结果列表的顺序必须与交互无关。曾经做过「当前文档置顶」——点一条命中，活动标签就变了，整张列表跟着重排，用户要点的第二条已经换到别处。列表可以变色，但不能换位。

6无障碍

项要求
正文对比度≥ 4.5:1。六级灰阶中 1–3 级达标（最低 6.6:1），4–6 级禁止用于正文
焦点环2px --mr-accent + 2px 偏移。任何情况下不得移除 outline
全键盘每个功能都要有快捷键，且不得占用系统级组合键
缩放Ctrl+= / Ctrl+- / Ctrl+0，80% – 200%，缩放后布局不得错位
动效尊重 prefers-reduced-motion，命中时全部过渡置 0
触控目标可点击区域最小 28×28，窗口控件 44×39

7禁止项

下面这些不是"建议"，是写进 code review checklist 的硬性禁止项。

✕ 大面积阴影与渐变
层级一律用 1px 细线。浮层除外（唯一允许 --mr-shadow-popover）
✕ 圆角 > 8px
超过就从「工具」滑向「消费级 App」，破坏编辑型阅读的克制感
✕ 饱和度 > 40% 的色
强调色 6.1:1 已达标，再加饱和只会抢正文的注意力
✕ 第二个强调色
每屏只允许一个 --mr-accent。青铜色只用于文件夹图标与警告点缀
✕ emoji 当图标
一律用 SVG 描边图标。emoji 在不同系统字体下渲染不一致，且基调不对
✕ 正文列宽 > 680px
窗口再宽也不放宽正文，多出的空间留给留白
✕ 正文居中 / 两端对齐
只有空态与引导页的说明文字可以居中
✕ 主题切换加过渡
会闪白。--mr-dur-theme: 0ms，硬切
✕ 设置项加「确定」按钮
全部即时生效 + 自动保存。可逆的视觉参数不需要确认
✕ 装饰性分隔线
线必须有功能含义（分组 / 边界），不能只是为了好看

# MoRead · 墨读

Windows 只读 Markdown 阅读器。**Tauri 2 + WebView2 + Svelte 5 + TypeScript。**

> V1 铁律：**对用户文档只读，零写入。**
> 这条约束砍掉了 undo/redo、光标模型、脏数据校验约 70% 的复杂度，
> 也是它同时能做到「小」和「稳」的原因。

---

## 怎么跑起来

双击 **`启动阅读器.bat`**。首次会自动装依赖（约 1 分钟），之后每次约 7 秒。
浏览器会自动打开 `http://localhost:1421`，**关掉那个黑窗口就等于停止服务**。

手动跑也可以：

```bash
npm install      # 首次
npm run dev      # 开发模式，端口 1420，改代码即时生效（有 HMR 开销，别用它测性能）
npm run preview  # 生产构建预览，端口 1421，性能接近最终形态 ← 日常用这个
```

### 打开 Markdown 的四种方式

| 方式 | 操作 | 说明 |
|---|---|---|
| **双击 .md** | 装好之后在资源管理器里双击任意 `.md` / `.markdown` | ✅ 最顺手。程序没开就冷启动，已在托盘里就转交给现有窗口 |
| **打开文件夹** | 空态点「打开文件夹」，选目录；或 `Ctrl+Shift+O` | 文件树、大纲、跨文件搜索、外部修改自动重载，都得先有工作区 |
| **打开文件** | 空态点「打开文件」；或 `Ctrl+O` | 走系统文件选择框，单篇阅读够用 |
| **拖拽** | 把 `.md`（或整个文件夹）拖进窗口 | 拖文件夹 = 建工作区 |

工作区路径会被记住，下次打开自动回到那里。
双击文件打开时，如果还没有工作区，会**把文件所在目录立为工作区** ——
否则侧栏是空的、跨文件搜索也没有范围，等于只开了一个孤立标签。

### 快捷键

`Ctrl+O` 打开文件 · `Ctrl+Shift+O` 打开文件夹 · `Ctrl+F` 全文搜索 ·
`Ctrl+B` 折叠侧栏 · `Ctrl+W` 关标签 · `Ctrl+Tab` 切标签 · `Ctrl+R` 重新扫描工作区 ·
`Ctrl+滚轮` / `Ctrl+=` / `Ctrl+-` 调正文字号，`Ctrl+0` 复位

### 标签页与托盘

- **打开一个文件就多一个标签**。重复打开同一篇会切回已有标签，不会开第二份
- **按住左键拖动标签可以换位置**。插入点按目标标签的中线判定：
  落在左半边插到它前面，右半边插到它后面，过程中显示一条 2px 的墨绿指示线
- **右键标签出菜单**：关闭 / 关闭其他 / 关闭左侧 / 关闭右侧 / 关闭全部 / 固定标签页。
  菜单会自己贴边收进窗口，不会跑到屏幕外
- **固定标签**：不显示关闭按钮，钉在标签栏上。`Ctrl+W`、鼠标中键、
  「关闭全部」等所有批量操作都会跳过它，并给出提示而不是静默失败
- **双击标签关闭它**。两条路特意排除：① 点在 × 上不算双击关闭——第一次点击已经
  把标签关掉了，第二次多半落在补位上来的另一个标签的 × 上，会连带关掉第二个；
  ② 拖拽结束后 250ms 内的双击不算——拖一下就把标签关掉没人想要
- 四种关闭方式：双击标签、标签上的 ×、`Ctrl+W`、鼠标中键点标签
- **标签多到装不下时**，按同类产品（浏览器 / 编辑器）收敛出来的同一条路走：
  1. **先缩宽**：220px → 100px 弹性收缩。一般十来份文档都还排得开
  2. **再收紧**：真装不下时（此时每个标签都已顶到 100px）撤掉文档图标 ——
     所有标签的图标长得一样、不携带信息，却占 19px，撤掉后名字能多认两个字
  3. **再滚动**：标签条横向滚动，竖向滚轮直接横推；活动标签永远自动追进视野
     （连按 `Ctrl+Tab`、或从侧栏打开排在末尾的文件，不会出现"点了没反应"）
  4. **兜底菜单**：右端出现 `⌄`，只列出**当前滚出视野**的那几个标签，点一下即切过去。
     菜单内容随滚动实时更新，数量写在提示语里

  收缩、收紧、滚动三档都只在"真装不下"时生效，排得开时标签保持自然宽度
- **关掉最后一个标签 → 回到启动界面**（Logo + 打开按钮 + 最近打开）。
  此时左侧文件树**保留**：既然还认得工作区，就没必要逼用户重新选一次文件夹
- **点右上角关闭 = 收起到右下角托盘**，不退出程序。左键托盘图标叫回窗口；
  右键菜单里有「显示主界面 / 退出 MoRead」。`Alt+F4` 走同一条路径
- **只允许跑一份**：程序在托盘里时再双击 exe，会把已有窗口叫回前台，
  而不是再开一个进程（否则会出现两个托盘图标，谁都分不清哪个是真的）

> 浏览器预览形态下没有托盘（`window.close()` 就是关标签页），
> 上面这套行为属于桌面版。桌面版见「Rust 外壳：已验证」。

### 侧栏：可拖宽、可折叠

`大纲 / 文件 / 历史` 那条左栏可以拖宽，范围 **200–480px**（默认 240）。搜索已经搬到右侧栏，见下一节。

**默认停在大纲**：打开软件先看到「这一篇有哪些节」。两个例外都不该按默认走 ——
URL 上显式带 `?ws=<目录>`（调试与自动化的入口，直接给文件树），
以及用户自己挑了一个文件夹（见 `openWorkspace` 里的 `changed` 分支）。
恢复上次会话不算例外：用户什么都没点，就该落到默认。

- **拖拽条骑在中缝上**：热区 7px、向两侧各溢出 3px。3px 的线没人点得中，
  而把它做成 flex 子项又会从正文里白扣 7px，还让"视觉分界线"和"手指位置"差半格
- **平时不画线**，就是侧栏原来那条 1px 边；悬停加粗成 `--mr-border-strong`，
  拖动时变成 2px 墨绿 —— 颜色变化用 `--mr-dur-hover`，和全站一个节奏
- **双击复位**为 240；键盘 `←/→` 每次 8px、`Shift` 32px、`Home/End` 到两端
  （`role="separator"` + `aria-valuenow`，读屏能报当前宽度）
- **上限看窗口**：480 在 1000px 宽的窗口里会把正文挤没，所以再压一道
  "正文至少留 420px"；窗口缩小时也会把宽度重新夹回来
- 宽度记在 `localStorage`，下次打开还是这个宽度

**折叠**：`Ctrl+B`，或点分段控件右边那个 `‹` 按钮。收起后**不是彻底消失**，
而是留一条 **44px 图标栏**（`--mr-rail-w`）：

- 三个模式图标竖排在顶部，当前模式用「白底 + 墨绿图标」标出来（和激活标签同一套语言）
- **点任一图标 = 展开并切到该模式**，不用先展开再切一次
- 底部单独放一个 `›` 展开按钮，沉底是为了不和上面三个模式图标误点
- 折叠不重置宽度：展开后还是折叠前的那个宽度；折叠时拖拽条一起隐藏

> 为什么不做成"彻底隐藏"：那样唯一的回头路就是 `Ctrl+B`，而这正是没人记得住的快捷键。
> 留 44px 等于把入口缩到最小，同时把"怎么展开"摆在明面上。

> 拖动期间整窗 `cursor: col-resize` 并禁选文字，否则指针滑到正文上会变 I 形、
> 顺手选中一段。
>
> 事件监听挂在 `window` 而不是靠 `setPointerCapture`：实测某些环境
> （CDP 注入的合成鼠标事件）捕获会**返回成功却不真的重定向事件**。
> 捕获有效时事件照样冒泡到 window，两条路都通。

### 历史：回到上次读的那一篇

侧栏第三页签。按打开时间倒序，最多 **24 条**，每条显示文件名、所在目录、相对时间。

- 点一下即打开；文件已在别的标签里打开时切过去，不会开第二份
- **启动时校验存在性**：并发对每条做一次 `stat`（不是 `read_text_file` —— 那会把
  24 篇文档读进内存只为回答一个是/否）。已经不存在的条目**画灰、`disabled`、标「已不存在」**
- **只有文件进历史**，目录记录（工作区）不混进来 —— 目录没有"重新打开"这回事
- 切到「历史」页签、以及每次启动，都会重新校验一遍：删掉的文件立刻变灰，
  放回去的文件立刻恢复可点
- 「清空」写回 `localStorage`；相对时间按时间戳现算（存下来的"3 分钟前"过一夜就是错的）

> **缺失状态刻意不落盘**：它是每次启动重新探测出来的**当下事实**。
> 存进 localStorage 就成了一份会过期的判断 —— 用户把文件放回去，列表还灰着。

> 无文件系统能力（静态托管）时一律不标灰：**"无法确认"不等于"已经不存在"**。
> 这时点了会走打开失败的提示，比错误地涂灰诚实。

### 右侧搜索栏：Ctrl+F 或点放大镜

搜索从左侧搬到了右侧，因为两者回答的是不同问题：左侧是"我的文档在哪"（导航，常驻），
右侧是"我在找一段内容"（临时任务，用完就收起）。

- 入口是标题栏主题按钮旁的**放大镜**；再点一次、点面板上的 `›`、`Esc` 都收起
- **三档范围**：`当前标签` / `所有标签` / `工作区`（含还没打开的文档）。
  没有工作区时第三档置灰。选择会记住
- **默认「所有标签」**：打开搜索栏多半是在手头这几篇里找东西；搜遍整个目录是另一个动作
- 结果按文件分组，组内列出命中行与片段（关键词高亮，不用 `{@html}`）
- 点结果直接跳转；目标文件没打开就先打开，再按 `ordinal` 落到**那一次**出现
- 面板占位后正文列宽自动收到 `min(680px, 可用宽度)`，不会被裁掉右半边

> 为什么不放在左侧栏：搜索结果通常比文件树长得多，右侧栏有整屏高度可以摊开；
> 而且搜索时正文还在读，左右分栏不打断视线。

### 主题：三色调 × 浅深 = 六套

点右上角的太阳／月亮，弹出**外观面板**：三行色调、两列浅深，点哪张色卡就用哪套。

| 色调 | 浅 | 深 |
|---|---|---|
| 暖纸 | `#F4F0E8` 暖白纸 + 松墨绿 | **暖墨** `#141413` 暖黑 + 提亮绿 |
| 竹青 | `#EDF2E8` 宣纸偏青 | **墨绿** `#0E1310` 绿黑 |
| 天青 | `#ECF1F7` 雨后青白 + 靛蓝 | **深蓝** `#0D1218` 蓝黑 |

- **两轴正交**：`data-theme` 管明暗、`data-palette` 管色相。六套共用同一套
  字号 / 圆角 / 间距 / 阴影，色值只在 tokens.css 里
- **面板选完不自动关**：调主题是眼睛在挑，连着点几套对比最快；点空白或 `Esc` 关
- **「跟随系统深浅」**只切明暗、不动色调 —— 白天晚上换亮度但仍然用竹青，是合理诉求
- **色卡不是画出来的色块**，而是给元素挂 `data-palette` / `data-theme`
  让令牌自己算，所以永远不会出现"色卡是旧配色"
- 选择存在 `localStorage`（`moread.theme` + `moread.palette`）；
  首帧由 `public/theme-boot.js` 先落属性，开机不会先画暖纸再跳竹青

> **每加一族必须在 tokens.css 写两个块**：`[data-palette="x"]` 与
> `[data-palette="x"][data-theme="dark"]`。漏了深色块 = 深色模式下仍是浅色纸底，
> 这是这套结构唯一容易犯的错。`tools/theme-check.mjs` 会把它查出来。

### 正文字号：12–22px，Ctrl + 滚轮直接调

外观面板里第二段就是字号：`−` / 当前值 / `+`，点数字复位 15。

- **Ctrl + 滚轮**一次一档（80ms 节流）。触控板一秒能发几十个 wheel 事件，
  不节流会把 15 直接推到底
- `Ctrl+=` / `Ctrl+-` / `Ctrl+0`（复位 15），和浏览器同一套手
- 只放大**阅读域**：在 `.mr-article` 上重算 11 组字号与行高令牌。标签页 / 侧栏 /
  面板读的仍是 `:root` 原值，一个像素都不会变
- 版心宽度不跟着变 —— 只放大字，不放大版心，行长才守得住
- 存在 `localStorage['moread.fs']`，首帧由 `theme-boot.js` 写 `--mr-read-scale`，
  开机不会先按 15px 排一遍再被拉大

> 为什么不用整页 `zoom`：那会把侧栏和工具栏一起放大，看起来像浏览器按错了键。
> 阅读器要调的是"字"，不是"界面"。

> 字号一变，虚拟滚动的高度估算**全部失效**（行高变了，每行装得下的字也变了）。
> `estimateContentHeight(..., scale)` 里的常量按倍率放大、`perLine` 按倍率缩小；
> 重算前用 `anchorAtPx` 记块号再还原 —— 与拖侧栏共用同一条重排路径。
> 2832 块的长文档从 15px 调到 20px，阅读位置只漂 1 块，DOM 仍只渲染 15 个块。

### 文件关联：双击 `.md` 直接打开

`tauri.conf.json` 里声明了 `bundle.fileAssociations`（`md` / `markdown`），
安装时由 NSIS 写入 `HKCU\Software\Classes`，卸载时清掉。**免安装版不写注册表**，
不会抢你的默认程序。

打开请求有两条完全不同的路径，都必须处理：

| 场景 | 路径 |
|---|---|
| 程序没开，双击 `.md` | 进程**带参数**启动 → Rust `setup` 阶段读 `std::env::args()` |
| 程序已在托盘里，又双击一篇 | 第二个实例被单实例插件拦下 → 回调里拿到 `argv`，转交给现有窗口 |

冷启动这一条有个容易漏的时序：**那一刻前端还没挂载，`emit` 出去没有任何监听者**。
所以 Rust 侧先把路径攒进一个队列（`PendingOpen`），前端 `onMount` 时调
`take_pending_open` 取走并清空。前端里**必须先注册事件监听、再取队列** ——
顺序反过来，两步之间进来的请求就没人接了。

两个坑，都踩过：

1. **`setTitle` 需要 capability 授权。** 我在 `default.json` 里漏了
   `core:window:allow-set-title`，调用被拒、又被 `catch` 吞掉，表现是
   「文件打开了但窗口标题不变」，完全看不出是权限问题。现在失败会 `console.warn`。
2. **命令行参数别用 Git Bash 传中文路径。** MSYS 的路径转换会把
   `C:\Users\...` 改写成 `C://Users//...`（能跑，但不是真实关联调用）。
   要模拟真实关联，用 PowerShell `Start-Process -ArgumentList`。

### 安装包少掉的那两次点击

Tauri 生成的 NSIS 安装包会多要两次交互，都不在配置项里，只能靠
`bundle.windows.nsis.installerHooks` 注入宏改。全部逻辑在
`src-tauri/installer-hooks.nsh`，配置里一行 `"installerHooks": "./installer-hooks.nsh"`。

**一、装完停在「已完成」，还要点一次「下一步」**

模板里有一行 `!define MUI_FINISHPAGE_NOAUTOCLOSE`，注释写明了理由：
“安装页上有可用于排查问题的信息，所以不要自动跳”。MUI2 实现这个开关的方式，
就是在结束页的初始化里跳过 `SetAutoClose true`。于是进度条走满之后页面不动，
看起来像是“装完了吗？好像没动”。

```nsis
!macro NSIS_HOOK_POSTINSTALL
  SetAutoClose true
!macroend
```

**二、程序开着就弹「点击确定以终止运行」**

模板在 Section 开头调 `CheckIfAppIsRunning`（走 RestartManager），弹的是
`MB_OKCANCEL`；只有 `/S` 静默模式才会不问直接杀。所以只要托盘里还挂着实例，
每次重装都得先点一下确定。

`NSIS_HOOK_PREINSTALL` 正好插在这次检测之前，于是先自己把实例关掉：

```nsis
!macro NSIS_HOOK_PREINSTALL
  nsExec::Exec 'taskkill /IM ${MAINBINARYNAME}.exe /F'
  Pop $0
  ${If} $0 == 0
    DetailPrint "Closed a running ${PRODUCTNAME} instance."
    Sleep 600
  ${EndIf}
!macroend
```

这么做的前提是**这个程序没有不可丢的未保存状态**：文档只读，设置与历史都是
随改随写 `localStorage`。代价只是阅读位置回滚到顶部。动作写进详情面板，
不弹框——要的就是“别问我，直接装”。

卸载段 `NSIS_HOOK_PREUNINSTALL` 用同一段，否则卸载时又是一模一样的框。

> 这个 `.nsh` **必须保持纯 ASCII**。NSIS 可能按系统 ANSI 代码页读被包含的文件，
> 中文注释在这里换不来任何收益，只换来一次编码赌博。

## 本轮新增（M6：标签手势）

三个交互都不复杂，但每一个都有一个「看起来能用、实际会坏」的细节。

**1. 拖动换位：拖拽事件会冒泡到窗口级处理器。**
`App` 在 `window` 上挂了「拖文件进窗口」的处理（拖入遮罩 + 只收 `.md` 的提示）。
标签之间拖动时，`dragover` / `drop` 一路冒上去，于是拖个标签会弹出
「只支持拖入 .md / .markdown 文件」，浏览器预览下还会拉起整屏的拖放遮罩。
**这个 bug 是自动化测试打出来的，不是看代码看出来的** ——
修法是在标签的 `dragover` / `drop` 里 `stopPropagation()`。

**2. 插入点用中线判定，不是「永远插左边」。**
拖到目标标签右半边就该插到它后面。反之用户在标签条上会发现自己永远只能往前插。
指示线是 2px 竖线（`::before` / `::after`），不是把目标标签整体位移 ——
位移会让整条标签栏在拖动时抖。

**3. 固定标签的拦截必须在逻辑层，不能只藏按钮。**
`Ctrl+W`、鼠标中键、批量关闭三条路都绕过那个 × 按钮。
所以 `closeTab()` 里第一件事是判 `pinned` 并给提示，`closeTabsBy()` 里
每一档（含「关闭全部」）都跳过固定标签，菜单项的禁用态也用同一套计数算 ——
**按钮禁用和真正行为必须对得上**，否则用户点了没反应比灰着更困惑。

右键菜单落在 `position: fixed` 上，先渲染再用 `getBoundingClientRect()`
量真实尺寸贴边收进来。用估算值会有几像素误差，菜单靠窗口右边缘时很明显。

## 此前：M5 标签页闭环与托盘

三个行为都是「用户以为理所当然、实现时各有坑」的那类需求。

**1. 关掉最后一个标签回主界面，但文件树留下。**
原来的条件是「有标签才显示侧栏」，关完最后一个标签左栏会整条消失 ——
可这时程序明明还认得工作区，让用户重新选一次文件夹纯属添堵。
改成「有标签**或**有工作区就显示侧栏」，主界面就是启动屏，左栏照常可浏览。

**2. 关闭按钮 = 收起到托盘。**
拦在 `WindowEvent::CloseRequested` 上，`api.prevent_close()` + `w.hide()`。
选这个位置而不是在前端改按钮逻辑，是因为**自绘关闭按钮、`Alt+F4`、系统窗口菜单
三条路都会走到这里**，只需处理一次。相应地，退出必须另开一个入口：
托盘菜单的「退出 MoRead」调 `app.exit(0)` —— 如果它去关窗，会被同一个拦截器再拦下，
变成永远关不掉。

**3. 单实例插件必须第一个注册。**
托盘应用允许开第二份的话，会出现两个托盘图标、两份内存，用户完全分不清。
`tauri-plugin-single-instance` 的回调里复用同一个 `show_main_window()`，
于是「再双击一次 exe」自然就成了把窗口叫回前台 —— 这既是防重复，也是找回隐藏窗口的
第二条路（第一条是点托盘图标）。

`show_main_window()` 三个调用缺一不可：`show()` 只让窗口可见，曾被最小化的仍是
最小化状态，`set_focus()` 才会抢焦点。少任何一个，用户都会以为程序没反应。

托盘图标直接用 `app.default_window_icon()` —— Windows 上它来自 exe 里嵌的 ico 资源，
所以 `Cargo.toml` 不必开 `image-png`。

## 此前：M3 工作区级全文搜索

**搜索的是磁盘，不是内存。** 打开工作区后，检索范围是整个工作区（含**尚未打开**的文档）；
没有工作区时退化为「搜已打开的标签」。两套后端（浏览器桥 / Rust）共用同一份匹配逻辑
（`src/lib/search.ts`），保证同一个关键词在哪都是同一个结果。

**点击命中能跨文件跳转。** 命中来自未打开的文档时，先读进来、建标签、等渲染完成，
再滚到那一处。跳转用 **`ordinal`（该文件内第几次出现）而不是行号** ——
行号是源文件的坐标，正文里根本没有这个概念。

### 一个不显眼但必须处理的坑：匹配序号会错位

搜索在**源 Markdown** 上做，跳转发生在**渲染后的正文**里。源文本里有一批匹配
在正文中根本不存在：

```markdown
参考 [报表规范](https://example.com/报表/规范)
```

用户搜「报表」，源文本命中 2 次（`报表规范` 与 URL 里各一次），正文里只有 1 次。
于是「点第 2 条」会跳到第 3 处 —— 序号整体前移。

解法是**等长屏蔽**（`maskNonVisible`）：把 `](...)` 与 `<...>` 这些不会出现在
渲染结果里的片段**按字符数**替换成空格。行号、列号、行长全部保持不变，
只是那些位置再也匹配不上。用码点遍历而不是正则替换，就是为了保证字符数严格相等。

### 其他几个判断

- **不建索引。** 2 万文件量级下流式扫描的端到端延迟（本机实测 4 ms / 4 个文件）
  已经低于感知阈值，而索引要额外维护一整套失效逻辑（增删改、编码变化），收益为负。
  真到十万文件量级再换 tantivy，接口不变。
- **搜索时防抖 220 ms，并用递增序号丢弃过期响应。** 快速输入时会有多个请求在途，
  先回来的可能是旧结果。
- **排序放在前端，且只按文件名。** 这样两套后端不必在「目录遍历顺序」上强求一致，
  那是文件系统的脾气，不是产品的语义。**刻意不做「当前文档置顶」**：点一条结果后
  活动标签会变，列表跟着重排，用户要点的第二条就换位置了。当前文档只用墨绿名字
  标出来，位置不动。

## 此前的里程碑（M1 / M2）

**真实工作区。** 侧栏文件树读的是磁盘上的真目录，支持多级展开、刷新（`Ctrl+R`）、
打开文件夹（`Ctrl+Shift+O`）。目录选择在浏览器预览下退化为内置路径面板。

**文件监听 + 自动重载。** 外部编辑器保存文件后，界面自动更新，并**把阅读位置放回原处**。
只记 `scrollTop` 是不够的 —— 内容长度一变，`scrollTop` 指向的已经是另一段文字。
实现上同时记住「视口顶部那个块」与「该处最近的标题 id」，重载后按标题对齐。

**长文档虚拟滚动。** 正文按顶层块虚拟化：只把视口附近的几十个块放进 DOM，
上下用 padding 顶住总高度。估高必然有误差，所以每次可见区间变化都实测一遍并写回，
且把「视口上方块的高度变化量」补偿回 `scrollTop` —— 不做这步，滚动时正文会抖。

**懒高亮。** 代码块在解析阶段只做转义，进入 DOM 后才交给 Shiki，并按帧分片（每帧 6 块）。
一篇 2.5MB 的文档有两千个代码块，其中绝大多数在虚拟滚动下根本不会出现。

**编码兜底。** UTF-8 严格解码失败时退到 GB18030，中文环境下老工具导出的 Markdown
经常是 GBK，直接按 UTF-8 读会得到满屏乱码。前端会在状态栏提示实际编码。

## 实测数据

测试文档：`tools/make-big-doc.mjs` 生成的 2.5 MB / 54,359 行 / 2,013 节 / 14,095 个块，
混合标题、长段落、列表、代码块、表格、引用 —— 块高度差异极大，是虚拟滚动最难的形态。

| 指标 | 虚拟滚动 | 全量渲染（`?novirtual=1`） |
|---|---|---|
| DOM 节点总数 | **188** | 76,240 |
| 实际渲染的块数 | **16** | 14,095 |
| 滚动帧中位 | **16.9 ms（59.2 fps）** | 153.9 ms（6.5 fps） |
| 滚动帧 p95 | **19.1 ms** | 189.9 ms |
| 打开耗时 | 4.56 s | 4.56 s |
| 估算总高 | 1,748,067 px | 1,735,465 px（真实值） |

几点说明：

- **打开耗时的瓶颈不在这里。** 4.5 s 里绝大部分是 markdown-it 解析 2.5 MB 文本本身，
  虚拟化几乎没有额外开销。这点代价换来 9 倍的滚动帧率，划算。
  真实笔记通常在几十 KB 到几百 KB，打开是百毫秒级。
- **估高准确度 0.7%。** 首屏测完立刻用「实测／估算」比例校准其余未实测的块，
  把累计误差一次压下去。不做校准的话偏差是 -9.6%，表现是滚动条长度失真、拖到底还剩一截。
- **测性能前必须重启 `npm run dev`。** 这条是用一次误判换来的：在同一台开发服务器上
  反复改文件后，HMR 会累积旧模块实例，实测帧率从 59 fps 掉到 31 fps，
  而**同一批代码重启后立刻回到 59 fps**。当时全量渲染的对照组也同步变慢，
  才排除掉「虚拟滚动退化」这个误判 —— 留着这个对照组是有用的。

### 为什么浏览器预览也能读真实磁盘

Tauri 需要 Rust + MSVC，门槛高、迭代慢。`tools/dev-fs.ts` 提供了四个只读端点
（`/__fs/list`、`/__fs/read`、`/__fs/watch`、`/__fs/search`），让浏览器预览也能访问真实文件系统。
前端靠 `platform.ts` 在后端之间切换，业务代码不感知差异。
**生产构建里不含这些代码**，它只在 dev / preview 服务器上挂中间件。

### 调试参数

| 参数 | 作用 |
|---|---|
| `?theme=light\|dark\|system` | 强制浅深（只影响本次会话，不落盘） |
| `?palette=paper\|moss\|blue` | 强制色调（同上，便于逐套截图核对） |

| `?novirtual=1` | 关闭虚拟滚动，作为性能对照 |

## 图标

一本翻开的书：**松墨绿为墨、暖纸为书页**，书脊处透出一道墨色折缝。

设计源是矢量图 `icons/icon.svg`，`tools/make-icons.mjs` 负责栅格化成
`src-tauri/icons/` 下的 `.ico`（16/24/32/48/64/128/256 七档）与打包所需散图。

```bash
node tools/make-icons.mjs                # 用 icons/icon.svg
node tools/make-icons.mjs --svg x.svg    # 换源，对比候选时用
node tools/icon-sheet.mjs                # 出验收图（尺寸阶梯 + 任务栏模拟）
```

形状有四条硬规则，每一条都是 16px 实测逼出来的：

| 规则 | 不这么做会怎样 |
|---|---|
| 书页外角**向上外翘** | 一放平，16px 就退化成一个白方块（卡片 / 窗口） |
| 外角用 Q **收一点圆** | 直角尖在 16px 磨出半透明白毛刺，糊成一团 |
| 书脊折缝宽 **3.6**、长 14.4 | 短而粗像一根黑棒；窄过 3.2 直接消失 |
| 两页在书脊**底部相连** | 变成两条独立白条，会被读成暂停键 |

底色必须是**松墨绿**而不是近黑：`#1F2A24` 贴在深色任务栏 `#202020` 上等于隐形，
只剩一页纸浮着。书页用 `#FDFAF3 → #EBE3D1` 的暖纸渐变，不用纯白。

被否掉的三个方向（源文件留在 `icons/candidates/`，可随时换回）：

| 方向 | 16px 下的实际读感 |
|---|---|
| 直角尖的翼展书（book7） | 128px 好看，但 16px 出白毛刺 |
| 书页下方加页缘厚度（book8） | 16px 多出一条暗边，像污渍 |
| 书页垂一条暖金书签（book9） | 16px 变成一个脏黄点 |

`tools/icon-preview.mjs` 出对照图，把候选按 16/32/48/128 摆开、
并把 16px 放大 8 倍（像素化）检查：**图标真正的考场是 16px，
按原尺寸看只会得到"还行"的错觉。**

栅格化走无头 Edge + CDP：本机 Edge 的 `--screenshot` 会静默失效
（退出码 0、不出图、连 `--dump-dom` 都是空的），而 CDP 能精确指定视口、
用 `Emulation.setDefaultBackgroundColorOverride` 拿到真正的透明底，
脚本里还会读四角 alpha 断言背景确实被抠掉了。

## 打包（已验证）

```bash
cd moread
npm run tauri build
```

| 产物 | 大小 | 说明 |
|---|---|---|
| `src-tauri/target/release/moread.exe` | **4.9 MB** | 免安装版，双击即用 |
| `.../bundle/nsis/MoRead_0.1.0_x64-setup.exe` | **2.60 MiB** | 安装包，用户级安装（不需要管理员） |

release profile（`lto` + `codegen-units=1` + `opt-level=s` + `strip`）把体积从 debug 的
15.8 MB 压到 4.9 MB。前端产物 3.3 MB 已内嵌进二进制，**运行不依赖任何 dev server** ——
实测关掉 1420 端口之后窗口照常打开。首次 release 构建约 11 分钟。

### 首次打包必踩：NSIS 工具链下不下来

`tauri build` 会从 GitHub Releases 拉 `nsis-3.13.zip` 和 `nsis_tauri_utils.dll`。
国内直连必然失败，报 `io: peer closed connection without sending TLS close_notify`，
而且**不会退化成「跳过打包」**，整个 build 直接失败（release exe 此时已经编好了）。

离线补齐，不用改任何配置——走的是 Tauri 自己的缓存目录：

```bash
GH=https://ghfast.top/          # 或 gh-proxy.com / ghproxy.net，实测这三个可用
TOOLS="$LOCALAPPDATA/tauri"     # ~/AppData/Local/tauri

# 1) NSIS 本体，SHA1 应为 DB14F8AF2EA346B786C6AE19343F61AAF5E09B8E
curl -L -o nsis.zip "$GH"https://github.com/tauri-apps/binary-releases/releases/download/nsis-3.13/nsis-3.13.zip
unzip -q nsis.zip -d "$TOOLS" && mv "$TOOLS/nsis-3.13" "$TOOLS/NSIS"

# 2) Tauri 的 NSIS 插件，SHA1 应为 75197FEE3C6A814FE035788D1C34EAD39349B860
mkdir -p "$TOOLS/NSIS/Plugins/x86-unicode/additional"
curl -L -o "$TOOLS/NSIS/Plugins/x86-unicode/additional/nsis_tauri_utils.dll" \
  "$GH"https://github.com/tauri-apps/nsis-tauri-utils/releases/download/nsis_tauri_utils-v0.5.3/nsis_tauri_utils.dll
```

放好后再跑 `npm run tauri build`，会直接跳到 `makensis`。

两个下载地址与 SHA1 是从 CLI 二进制 `node_modules/@tauri-apps/cli-win32-x64-msvc/cli.win32-x64-msvc.node`
里挖出来的常量。**不要拿别处的 NSIS 顶上** —— 它内部有一张文件哈希表
（例如 `NSIS.exe` 必须是 `6d45d4e8ccf18fe1fdac9164058f356102a2ecf2`），对不上会重新联网下载。

> `bundle.useLocalToolsDir: true` 可把工具缓存改到项目 `target/` 下，CI 场景更合适。

## 仍未验证 / 待办

- **托盘图标的鼠标交互只能人工验证**：左键显示、右键菜单在 Windows 托盘里
  没有脚本可用的事件入口。已用等价路径覆盖同一套逻辑 ——
  `CloseMainWindow()`（就是 WM_CLOSE，与点关闭按钮同一条路）证明窗口确实被收起、
  进程仍存活；再启动第二个实例证明 `show_main_window()` 能把窗口叫回前台
- **安装流程本身没在实际系统里跑过**：安装包已生成并通过 PE/元数据校验，
  但没有真的执行安装（会改开始菜单与注册表卸载项）。要验证就直接双击它
- **桌面端的标签拖拽没有实机点过**（下面这条限制导致的）。源码层面确认可行：
  Tauri 的拖动区域脚本遇到 `role="tab"` 会判定为可点击元素并直接放行，
  不会 `preventDefault`，所以 HTML5 拖拽能正常开始
- **右键菜单没有键盘入口**（`Shift+F10` / 菜单键）。鼠标路径完整，
  键盘路径未做 —— 属于可访问性欠账
- **桌面版的文件监听与原生目录选择器**只能人工验证：WebView2 不接受
  `--remote-debugging-port`（Tauri 用自己的 `additionalBrowserArgs` 覆盖了环境变量，
  试过改环境变量与改配置两条路都不生效），所以没法像浏览器端那样用 CDP 驱动
- **无工作区时的「标签内检索」路径没有自动化覆盖。** 它复用同一份 `searchInText`，
  但触发条件（没有工作区、只有内存里的标签）在浏览器自动化里不好构造，目前靠人工验证
- **超大单个块无法虚拟化**：一个上万行的代码块仍会一次性渲染
- **CRLF / 混合换行**未见明显问题，但没有针对性测试
- 设置页、Mermaid、导出 PDF、专注模式（`F11`）尚未接入
- 文件监听在大目录（几万文件）下的开销未实测
- 搜索命中上限（单文件 30 条 / 全局 300 条）目前是硬编码，还没有设置项
